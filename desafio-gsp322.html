📝 Como identificar os valores para substituir Nesta página, todo valor em amarelo é um placeholder: troque pelo valor do seu lab. O nome em amarelo é exatamente o nome do campo no painel do lab (à esquerda do roteiro, depois de clicar em Iniciar laboratório). Passe o mouse (ou toque) sobre o valor em amarelo para ver onde encontrá-lo.
  • SSH IAP network tag: tag do SSH pelo IAP, usada no bastion (passo 3);
  • HTTP network tag: tag do HTTP público, usada no juice-shop (passo 4);
  • SSH internal network tag: tag do SSH vindo do bastion, usada no juice-shop (passo 5);
  • Zone: zona das VMs (passo 6).
Exemplo: se o painel mostra HTTP network tag = permit-http-ingress-ql-123, digite permit-http-ingress-ql-123 onde a página mostra HTTP network tag.
Cenário e objetivo O site juice-shop do Jeferson está na VPC acme-vpc, com uma configuração de firewall aberta demais. Ao final:
  • o bastion host não tem IP público e só recebe SSH vindo do IAP;
  • o juice-shop só recebe SSH vindo do bastion (sub-rede acme-mgmt-subnet);
  • só o HTTP (porta 80) do juice-shop fica aberto ao público.
O roteiro avisa: permissões muito flexíveis são marcadas como incorretas. Nunca use 0.0.0.0/0 nas regras de SSH.

🗺️ Quem é quem na rede
  • acme-vpc: a rede privada (VPC) do Jeferson no Google Cloud. Todas as VMs do lab ficam nela, e as regras de firewall que você criar devem ser dela.
  • acme-mgmt-subnet: sub-rede de gerenciamento. Fica nela só o que a equipe usa para administrar o ambiente, no caso o bastion.
  • acme-app-subnet: sub-rede da aplicação. Fica nela o servidor que atende os clientes, o juice-shop.
  • bastion (bastion host): a "portaria" da rede. É a única VM em que o administrador entra por SSH; dali ele salta para os outros servidores. Por isso não tem IP público e só aceita SSH vindo do IAP.
  • juice-shop: o servidor web da loja. Os clientes acessam o site por HTTP (porta 80). O SSH nele só é aceito quando vem do bastion.
  • IAP (Identity-Aware Proxy): serviço do Google que confere a identidade do administrador (login e permissões) e só então abre o túnel SSH até o bastion. As conexões chegam sempre da faixa 35.235.240.0/20.
  • Admin: quem administra o ambiente. Entra pelo IAP › bastion › juice-shop.
  • Customers: os clientes da loja. Só chegam ao juice-shop, e só por HTTP.
  • Regras de firewall + tags de rede: a regra diz o que está liberado (porta e origem) e a tag diz em qual VM a regra vale. Uma regra só tem efeito na VM que tem a mesma tag.

1. Remover as regras excessivamente flexíveis10 pontos

  1. Menu de navegação (☰) › VPC network › Firewall.
  2. Na lista, localize a regra open-access da rede acme-vpc. Ela tem Filters IP ranges: 0.0.0.0/0 e Protocols / ports tcp, ou seja, libera todas as portas TCP (inclusive o SSH, porta 22) para a internet inteira. Por isso é "excessivamente flexível".
  3. Marque a caixa da regra e clique em Delete.
  4. Na janela de confirmação, clique em Delete.

Deixe as demais regras como estão.

Volte ao roteiro e clique em Verificar meu progresso de "Remova regras excessivamente flexíveis".

2. Iniciar o bastion host10 pontos

  1. Menu de navegação (☰) › Compute Engine › VM instances.
  2. Na linha da VM bastion (está parada), clique em ⋮ (More actions) › Start / Resume.
  3. Na janela de confirmação, clique em Start. Espere o ícone verde aparecer.
  4. Confira o IP público: na coluna External IP, o bastion deve aparecer sem endereço. Se tiver um IP, clique no nome bastion › Edit › Network interfaces › abra a interface › em External IPv4 address, selecione a opção None › Done › Save.

Volte ao roteiro e clique em Verificar meu progresso de "Inicie a instância do Bastion Host".

3. SSH pelo IAP para o bastion20 pontos

Criar a regra de firewall

  1. Menu de navegação (☰) › VPC network › Firewall e clique em Create firewall rule.
  2. Name: um nome à sua escolha, por exemplo allow-ssh-iap.
  3. Network: selecione a opção acme-vpc (não use default).
  4. Direction of traffic: Ingress · Action on match: Allow.
  5. Targets: selecione a opção Specified target tags · Target tags: SSH IAP network tag (tecle Enter).
  6. Source filter: IPv4 ranges · Source IPv4 ranges: 35.235.240.0/20 (é a faixa fixa do serviço IAP).
  7. Protocols and ports: Specified protocols and ports › marque TCP › Ports: 22.
  8. Clique em Create.

Colocar a tag no bastion

  1. Menu de navegação (☰) › Compute Engine › VM instances e clique no nome bastion.
  2. No topo da página da VM, clique em Edit.
  3. Role até a seção Networking e, no campo Network tags, digite SSH IAP network tag e tecle Enter. Não apague as tags que já existirem.
  4. Role até o fim da página e clique em Save.

Volte ao roteiro e clique em Verificar meu progresso do passo 3.

4. HTTP público para o juice-shop20 pontos

Criar a regra de firewall

  1. Menu de navegação (☰) › VPC network › Firewall e clique em Create firewall rule.
  2. Name: por exemplo allow-http.
  3. Network: selecione a opção acme-vpc.
  4. Direction of traffic: Ingress · Action on match: Allow.
  5. Targets: selecione a opção Specified target tags · Target tags: HTTP network tag.
  6. Source filter: IPv4 ranges · Source IPv4 ranges: 0.0.0.0/0 (aqui é público, como o roteiro pede).
  7. Protocols and ports: Specified protocols and ports › marque TCP › Ports: 80.
  8. Clique em Create.

Colocar a tag no juice-shop

  1. Menu de navegação (☰) › Compute Engine › VM instances e clique no nome juice-shop.
  2. No topo da página da VM, clique em Edit.
  3. Role até a seção Networking e, no campo Network tags, digite HTTP network tag e tecle Enter.
  4. Clique em Save.

Volte ao roteiro e clique em Verificar meu progresso do passo 4.

5. SSH do bastion para o juice-shop20 pontos

Descobrir o intervalo da sub-rede de gerenciamento

  1. Menu de navegação (☰) › VPC network › VPC networks e clique em acme-vpc.
  2. Abra a aba Subnets e confira o Internal IP ranges da acme-mgmt-subnet. Neste lab ele é fixo: 192.168.10.0/24. Se no seu aparecer outro valor, use o que aparecer.

Criar a regra de firewall

  1. Menu de navegação (☰) › VPC network › Firewall e clique em Create firewall rule.
  2. Name: por exemplo allow-ssh-mgmt.
  3. Network: selecione a opção acme-vpc.
  4. Direction of traffic: Ingress · Action on match: Allow.
  5. Targets: selecione a opção Specified target tags · Target tags: SSH internal network tag.
  6. Source filter: IPv4 ranges · Source IPv4 ranges: 192.168.10.0/24 (o intervalo da acme-mgmt-subnet).
  7. Protocols and ports: Specified protocols and ports › marque TCP › Ports: 22.
  8. Clique em Create.

Colocar a tag no juice-shop

  1. Menu de navegação (☰) › Compute Engine › VM instances e clique no nome juice-shop.
  2. No topo da página da VM, clique em Edit.
  3. Role até a seção Networking e, no campo Network tags, digite SSH internal network tag e tecle Enter. A HTTP network tag do passo 4 deve continuar lá.
  4. Clique em Save.

Volte ao roteiro e clique em Verificar meu progresso do passo 5.

6. Conectar ao bastion pelo IAP e ao juice-shop pelo bastion20 pontos

  1. Menu de navegação (☰) › Compute Engine › VM instances.
  2. Na linha do bastion, clique em SSH. Uma janela abre e se conecta pelo IAP (o bastion não tem IP público). Se pedir, clique em Authorize.
Por comando (dentro da janela SSH do bastion) Esta é a única parte que exige comando, porque a conexão sai de dentro do bastion. Rode os blocos um de cada vez, trocando Zone.

1. Conectar ao juice-shop pelo IP interno:

gcloud compute ssh juice-shop --internal-ip --zone=Zone

Se perguntar Do you want to continue (Y/n)?, digite Y e tecle Enter. Se pedir uma passphrase, só tecle Enter duas vezes (deixe em branco).

2. Conferir que está no juice-shop: o prompt muda para algo como usuario@juice-shop:~$. Se quiser confirmar:

hostname

Com a conexão aberta, volte ao roteiro e clique em Verificar meu progresso do passo 6.

⚠️ Erros comuns clique para abrir
  • Criar a regra na rede default em vez da acme-vpc: a regra não vale para as VMs do lab.
  • Criar a regra mas esquecer de colocar a tag na VM (ou clicar em Save).
  • Usar 0.0.0.0/0 nas regras de SSH: é marcado como permissão excessiva.
  • Digitar a tag errada: copie do roteiro, letra por letra. A tag da regra e a da VM precisam ser idênticas.
  • Botão SSH do bastion não conecta: confira a regra do IAP (35.235.240.0/20, TCP 22) e a SSH IAP network tag no bastion. O roteiro sugere rodar o comando com --troubleshoot para ver o motivo.
  • Nomes de botões diferentes dos desta página: a tradução automática do navegador está ligada. Veja "Antes de começar".
