🎯 Cenário e objetivo clique para abrir

Você trabalha numa consultoria de segurança contratada pelo Jeferson. O site da loja dele, o juice-shop, está funcionando, mas com a rede aberta demais. Sua missão é deixar aberto só o que precisa ficar aberto: o site para os clientes, e o acesso de administração por um único caminho controlado.

🧰 Os serviços e elementos da rede

  • VPC acme-vpc: a rede privada do Jeferson no Google Cloud. Todas as VMs do lab ficam nela, e as regras de firewall que você criar devem ser dela.
  • Sub-redes: divisões da VPC. A acme-mgmt-subnet é a de gerenciamento, onde fica o bastion. A acme-app-subnet é a da aplicação, onde fica o juice-shop.
  • Compute Engine (VMs): o bastion é a "portaria" da rede, a única VM em que o administrador entra por SSH, sem IP público. O juice-shop é o servidor web da loja.
  • Firewall da VPC: regras que dizem o que pode entrar (porta e origem). Por padrão, tudo o que não está liberado é bloqueado.
  • Tags de rede: etiquetas nas VMs que dizem em qual VM cada regra vale. Uma regra só tem efeito na VM que tem a mesma tag.
  • IAP (Identity-Aware Proxy): serviço do Google que confere a identidade do administrador (login e permissões) e só então abre o túnel SSH até o bastion. As conexões chegam sempre da faixa 35.235.240.0/20.

🔗 O que cada tarefa faz

  • Passo 1 · Firewall
    O que faz: remove a regra open-access.
    Para que serve: fechar a "porta escancarada" que liberava todas as portas TCP, inclusive o SSH, para a internet inteira.
  • Passo 2 · Compute Engine
    O que faz: liga o bastion, que estava parado.
    Para que serve: colocar no ar a única porta de entrada para a administração.
  • Passo 3 · Firewall · IAP · tag SSH IAP network tag
    O que faz: libera SSH (porta 22) no bastion, só vindo do IAP.
    Para que serve: o administrador entra no bastion sem que ele precise de IP público, e só depois de o Google confirmar quem ele é.
  • Passo 4 · Firewall · tag HTTP network tag
    O que faz: libera HTTP (porta 80) no juice-shop para qualquer origem.
    Para que serve: os clientes acessam a loja. É a única coisa que fica aberta para o público.
  • Passo 5 · Firewall · tag SSH internal network tag
    O que faz: libera SSH no juice-shop só vindo da acme-mgmt-subnet.
    Para que serve: o servidor da loja só aceita administração que vem de dentro, pelo bastion.
  • Passo 6 · IAP › bastion › juice-shop
    O que faz: conecta ao bastion pelo IAP e, de lá, ao juice-shop.
    Para que serve: provar que o caminho de administração funciona do começo ao fim.
💡 Na prática, o que o conjunto faz Os passos aplicam o padrão de segurança chamado bastion host, com defesa em camadas:
  • clientes chegam só ao site, pela porta 80;
  • administradores passam por um único ponto controlado: IAP › bastion › juice-shop;
  • todo o resto fica fechado, e cada regra vale só para a VM certa, graças às tags.
Com isso, a "superfície de ataque" diminui muito: mesmo que alguém descubra o IP do juice-shop, não consegue entrar por SSH vindo da internet. É assim que empresas protegem servidores de produção.

1. Remover as regras excessivamente flexíveis10 pontos

  1. Menu de navegação (☰) › VPC network › Firewall.
  2. Na lista, localize a regra open-access. Nas colunas, ela mostra Targets Apply to all, Protocols / ports tcp e Network acme-vpc. Ou seja, ela libera todas as portas TCP (inclusive o SSH, porta 22) em todas as VMs da rede, para a internet inteira. Por isso é "excessivamente flexível".
  3. Marque a caixa da regra e clique em Delete.
  4. Na janela de confirmação, clique em Delete.

Deixe as demais regras como estão.

Volte às instruções do lab no Google Skills e clique em Verificar meu progresso de "Remova regras excessivamente flexíveis".

2. Iniciar o bastion host10 pontos

  1. Menu de navegação (☰) › Compute Engine › VM instances.
  2. Localize a VM bastion. Ela está parada: na coluna Status aparece o ícone de parada (■), Stopped.
  3. Marque a caixa de seleção à esquerda do nome bastion.
  4. Na barra logo acima da lista, clique em Start / Resume. Se aparecer uma confirmação, clique em Start.
  5. Espere o Status mudar para o ícone verde (Running).
  6. O bastion já vem sem IP externo (coluna External IP vazia), como as instruções do lab exigem. Não altere isso.

Volte às instruções do lab no Google Skills e clique em Verificar meu progresso de "Inicie a instância do Bastion Host".

3. SSH pelo IAP para o bastion20 pontos

Criar a regra de firewall

  1. Menu de navegação (☰) › VPC network › Firewall e clique em Create firewall rule.
  2. Name: um nome à sua escolha, por exemplo allow-ssh-iap.
  3. Network: selecione a opção acme-vpc (não use default).
  4. Direction of traffic: Ingress · Action on match: Allow.
  5. Targets: selecione a opção Specified target tags · Target tags: SSH IAP network tag (tecle Enter).
  6. Source filter: IPv4 ranges · Source IPv4 ranges: 35.235.240.0/20 (é a faixa fixa do serviço IAP).
  7. Protocols and ports: Specified protocols and ports › marque TCP › Ports: 22.
  8. Clique em Create.

Colocar a tag no bastion

  1. Menu de navegação (☰) › Compute Engine › VM instances e clique no nome bastion.
  2. No topo da página da VM, clique em Edit.
  3. Role até a seção Networking e, no campo Network tags, digite SSH IAP network tag e tecle Enter. Não apague as tags que já existirem.
  4. Role até o fim da página e clique em Save.

Volte às instruções do lab no Google Skills e clique em Verificar meu progresso do passo 3.

4. HTTP público para o juice-shop20 pontos

Criar a regra de firewall

  1. Menu de navegação (☰) › VPC network › Firewall e clique em Create firewall rule.
  2. Name: por exemplo allow-http.
  3. Network: selecione a opção acme-vpc.
  4. Direction of traffic: Ingress · Action on match: Allow.
  5. Targets: selecione a opção Specified target tags · Target tags: HTTP network tag.
  6. Source filter: IPv4 ranges · Source IPv4 ranges: 0.0.0.0/0 (aqui é público, como o roteiro pede).
  7. Protocols and ports: Specified protocols and ports › marque TCP › Ports: 80.
  8. Clique em Create.

Colocar a tag no juice-shop

  1. Menu de navegação (☰) › Compute Engine › VM instances e clique no nome juice-shop.
  2. No topo da página da VM, clique em Edit.
  3. Role até a seção Networking e, no campo Network tags, digite HTTP network tag e tecle Enter.
  4. Clique em Save.

5. SSH do bastion para o juice-shop20 pontos

Descobrir o intervalo da sub-rede de gerenciamento

  1. Menu de navegação (☰) › VPC network › VPC networks e clique em acme-vpc.
  2. Abra a aba Subnets e confira o Internal IP ranges da acme-mgmt-subnet. Neste lab ele é fixo: 192.168.10.0/24. Se no seu aparecer outro valor, use o que aparecer.

Criar a regra de firewall

  1. Menu de navegação (☰) › VPC network › Firewall e clique em Create firewall rule.
  2. Name: por exemplo allow-ssh-mgmt.
  3. Network: selecione a opção acme-vpc.
  4. Direction of traffic: Ingress · Action on match: Allow.
  5. Targets: selecione a opção Specified target tags · Target tags: SSH internal network tag.
  6. Source filter: IPv4 ranges · Source IPv4 ranges: 192.168.10.0/24 (o intervalo da acme-mgmt-subnet).
  7. Protocols and ports: Specified protocols and ports › marque TCP › Ports: 22.
  8. Clique em Create.

Colocar a tag no juice-shop

  1. Menu de navegação (☰) › Compute Engine › VM instances e clique no nome juice-shop.
  2. No topo da página da VM, clique em Edit.

  4. Clique em Save.

6. Conectar ao bastion pelo IAP e ao juice-shop pelo bastion20 pontos

  1. Menu de navegação (☰) › Compute Engine › VM instances.
  2. Na linha do bastion, clique em SSH. Uma janela abre e se conecta pelo IAP (o bastion não tem IP público). Se pedir, clique em Authorize.
Por comando (dentro da janela SSH do bastion) Esta é a única parte que exige comando, porque a conexão sai de dentro do bastion. Rode o comando abaixo, trocando Zone.

Conectar ao juice-shop pelo IP interno:

gcloud compute ssh juice-shop --internal-ip --zone=Zone

Se perguntar Do you want to continue (Y/n)?, digite Y e tecle Enter. Se pedir uma passphrase, só tecle Enter duas vezes (deixe em branco).

Com a conexão aberta, volte às instruções do lab no Google Skills e clique em Verificar meu progresso do passo 6.

⚠️ Erros comuns clique para abrir
  • Criar a regra na rede default em vez da acme-vpc: a regra não vale para as VMs do lab.
  • Criar a regra mas esquecer de colocar a tag na VM (ou clicar em Save).
  • Usar 0.0.0.0/0 nas regras de SSH: é marcado como permissão excessiva.
  • Digitar a tag errada: copie do painel do lab, letra por letra. A tag da regra e a da VM precisam ser idênticas.
  • Botão SSH do bastion não conecta: confira a regra do IAP (35.235.240.0/20, TCP 22) e a SSH IAP network tag no bastion. O roteiro sugere rodar o comando com --troubleshoot para ver o motivo.
  • Nomes de botões diferentes dos desta página: a tradução automática do navegador está ligada. Veja "Antes de começar".
