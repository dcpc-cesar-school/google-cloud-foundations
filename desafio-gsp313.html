Tarefa 1: criar três servidores web20 pontos

O que o roteiro pede: três VMs (web1, web2, web3) com Apache e a regra de firewall www-firewall-network-lb liberando HTTP.

O que muda em cada VM Você vai criar 3 VMs com o mesmo roteiro. Em cada uma, altere só estes campos e deixe o resto como está: nome, região, zona, tipo de máquina, versão do Debian, tag de rede e script de inicialização.

Precisa de sudo no script? Não. O script de inicialização (startup script) já roda como root quando a VM liga, então os comandos funcionam sem sudo. Use o script exatamente como está abaixo.
Por que conferir o log Às vezes, logo após ligar a VM, o próprio Debian já está usando o instalador de pacotes. O script encontra o instalador ocupado (Could not get lock), não instala o Apache e termina com erro. Não é erro seu: um Reset resolve.

Criar a VM web1

  1. Navigation menu (☰) › Compute Engine › VM instances e clique em Create instance.
  2. Em Machine configuration:
    • Name: web1
    • Region: REGIÃO  ·  Zone: ZONA
    • Series: selecione a opção E2
    • Machine type: selecione a opção e2-small
  3. No menu à esquerda, clique em OS and storage e depois em Change:
    • Operating system: Debian
    • Version: Debian GNU/Linux 12 (bookworm) com x86/64 (não escolha a opção Arm64)
    • clique em Select.
  4. No menu à esquerda, clique em Networking. Em Network tags, digite network-lb-tag e tecle Enter.
  5. No menu à esquerda, clique em Advanced. Em Automation › Startup script, cole: 
    #!/bin/bash
apt-get update
apt-get install apache2 -y
service apache2 restart
echo "<h3>Servidor da web: web1</h3>" | tee /var/www/html/index.html
  6. Clique em Create e espere a web1 aparecer com o ícone verde na lista.
  7. Confira no log se o Apache foi instalado:
    1. Na lista de VM instances, clique no nome web1.
    2. Na aba Details, em Logs, clique em Serial port 1 (console).
    3. Aguarde 1 a 2 minutos e clique em Refresh. Use Ctrl+F e procure por startup-script.
    4. Deu certo se aparecer Setting up apache2 e não aparecer failed with error. Siga para a próxima VM.
    5. Falhou se aparecer Could not get lock, apache2.service not found ou Script "startup-script" failed with error. Faça o reset abaixo.
  8. Se falhou, clique em Reset: volte a VM instances, na linha da web1 clique em ⋮ (More actions) › Reset e confirme em Reset. O script roda de novo quando a VM reinicia. Espere 2 minutos e confira o log outra vez, olhando as últimas linhas: a falha anterior continua aparecendo mais acima.

Criar a regra de firewall

  1. Navigation menu › VPC network › Firewall e clique em Create firewall rule.
  2. Name: www-firewall-network-lb.
  3. Network: default · Direction of traffic: Ingress · Action on match: Allow.
  4. Targets: Specified target tags · Target tags: network-lb-tag.
  5. Source filter: IPv4 ranges · Source IPv4 ranges: 0.0.0.0/0.
  6. Protocols and ports: Specified protocols and ports › marque TCP › Ports: 80.
  7. Clique em Create.

Testar os três servidores web

  1. Volte a Navigation menu › Compute Engine › VM instances.
  2. Na linha de cada VM, clique no endereço da coluna External IP. Uma nova aba abre e deve mostrar Servidor da web: web1 (ou web2, web3).
  3. Se não abrir:
    • confira se o endereço começa com http://. Se o navegador trocar para https://, apague o "s" e tecle Enter;
    • confira o log da VM (passo "Confira no log" acima) e, se falhou, faça o Reset;
    • confira a tag network-lb-tag na VM e a regra www-firewall-network-lb.

Tarefa 2: configurar o balanceador de rede35 pontos

O que o roteiro pede: IP externo estático network-lb-ip-1, pool de destino www-pool e encaminhamento na porta 80.

Pelo console: reservar o IP estático

  1. Navigation menu › VPC network › IP addresses e clique em Reserve external static IP address.
  2. Name: network-lb-ip-1.
  3. IP version: IPv4 · Type: Regional · Region: REGIÃO.
  4. Clique em Reserve.
Por comando (o console não cria pool de destino)
  1. No topo do console, clique em Activate Cloud Shell (ícone >_) e depois em Continue. Se pedir, clique em Authorize.
  2. Rode os comandos abaixo, trocando REGIÃO e ZONA:
gcloud compute http-health-checks create basic-check

gcloud compute target-pools create www-pool \
  --region=REGIÃO --http-health-check basic-check

gcloud compute target-pools add-instances www-pool \
  --instances web1,web2,web3 --instances-zone=ZONA

gcloud compute forwarding-rules create www-rule \
  --region=REGIÃO --ports 80 \
  --address network-lb-ip-1 --target-pool www-pool

Conferir: em Network services › Load balancing aparece o balanceador com o pool www-pool. Abra o IP network-lb-ip-1 no navegador e atualize algumas vezes: a resposta alterna entre web1, web2 e web3.

Volte ao roteiro e clique em Verificar meu progresso da tarefa 2.

Tarefa 3: criar o balanceador HTTP45 pontos

O que o roteiro pede: modelo lb-backend-template, grupo gerenciado lb-backend-group, firewall fw-allow-health-check, IP lb-ipv4-1, verificação http-basic-check, mapa de URL web-map-http e proxy http-lb-proxy.

1. Modelo de instância (console)

  1. Navigation menu › Compute Engine › Instance templates e clique em Create instance template.
  2. Name: lb-backend-template.
  3. Location: Regional · Region: REGIÃO.
  4. Machine configuration: Series E2 · Machine type e2-medium.
  5. Boot disk › Change: Debian GNU/Linux 12 (bookworm) (igual às VMs da tarefa 1) › Select.
  6. Abra Advanced options › Networking e, em Network tags, digite allow-health-check e tecle Enter.
  7. Em Advanced options › Management › Automation › Startup script, cole (recomendado, para o teste final mostrar a página): 
    #!/bin/bash
apt-get update
apt-get install apache2 -y
a2ensite default-ssl
a2enmod ssl
vm_hostname="$(curl -H "Metadata-Flavor:Google" \
http://169.254.169.254/computeMetadata/v1/instance/name)"
echo "Page served from: $vm_hostname" | tee /var/www/html/index.html
systemctl restart apache2
  8. Clique em Create.

2. Grupo gerenciado de instâncias (console)

  1. Navigation menu › Compute Engine › Instance groups e clique em Create instance group.
  2. No menu à esquerda, escolha New managed instance group (stateless).
  3. Name: lb-backend-group · Instance template: lb-backend-template.
  4. Location: Single zone · Region: REGIÃO · Zone: ZONA.
  5. Autoscaling: Minimum number of instances 2.
  6. Em Port mapping, clique em Add port: Port name http · Port number 80.
  7. Clique em Create. O grupo leva 1 ou 2 minutos para subir as VMs.

3. Firewall para as verificações de integridade (console)

  1. Navigation menu › VPC network › Firewall e clique em Create firewall rule.
  2. Name: fw-allow-health-check.
  3. Network: default · Direction of traffic: Ingress · Action on match: Allow.
  4. Targets: Specified target tags · Target tags: allow-health-check.
  5. Source filter: IPv4 ranges · Source IPv4 ranges: 130.211.0.0/22 e 35.191.0.0/16 (tecle Enter depois de cada um).
  6. Protocols and ports: Specified protocols and ports › marque TCP › Ports: 80.
  7. Clique em Create.

4. IP externo global (console)

  1. Navigation menu › VPC network › IP addresses e clique em Reserve external static IP address.
  2. Name: lb-ipv4-1.
  3. IP version: IPv4 · Type: Global.
  4. Clique em Reserve.
5. Balanceador por comando (os nomes exigidos não são configuráveis no console) No Cloud Shell, rode os comandos abaixo, trocando ZONA: 
gcloud compute health-checks create http http-basic-check --port 80

gcloud compute backend-services create web-backend-service \
  --protocol=HTTP --port-name=http \
  --health-checks=http-basic-check --global

gcloud compute backend-services add-backend web-backend-service \
  --instance-group=lb-backend-group \
  --instance-group-zone=ZONA --global

gcloud compute url-maps create web-map-http \
  --default-service web-backend-service

gcloud compute target-http-proxies create http-lb-proxy \
  --url-map web-map-http

gcloud compute forwarding-rules create http-content-rule \
  --address=lb-ipv4-1 --global \
  --target-http-proxy=http-lb-proxy --ports=80

Conferir (pelo console): Network services › Load balancing › clique em web-map-http. Copie o IP em Frontend e abra http://IP-do-balanceador/. Pode levar de 3 a 5 minutos; aparece "Page served from: lb-backend-group-xxxx".

Volte ao roteiro e clique em Verificar meu progresso da tarefa 3.

Erros comuns
  • VM em zona errada ou sem a tag de rede: o firewall não se aplica.
  • Esquecer a porta nomeada http:80 no grupo: o serviço de back-end não encontra a porta.
  • Testar o HTTP antes de 5 minutos e achar que falhou. Aguarde e atualize.
  • Apache não instalado (Could not get lock no Serial port 1 (console)): clique em Reset na VM. No balanceador HTTP, isso vale para as VMs lb-backend-group-xxxx.
  • Nomes de botões diferentes dos desta página: a tradução automática do navegador está ligada. Veja "Antes de começar".
