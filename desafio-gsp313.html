🔀 GSP313 – Implementar o balanceamento de carga no Compute Engine

Selo de habilidade: Implementação do Cloud Load Balancing no Compute Engine

Antes de começar

Regras de ouro
  • Abra o lab em janela anônima e use só o usuário e a senha do laboratório.
  • Os valores em amarelo (nomes, região e zona) mudam a cada execução: copie do painel do lab, à esquerda do roteiro.
  • Faça pelo console. Use comandos apenas onde esta página indicar, e sempre no Cloud Shell do projeto do lab.
  • Ao final de cada tarefa, clique em Verificar meu progresso. Se não passar, leia a mensagem, corrija e verifique de novo.
  • Não clique em Terminar o laboratório antes de todas as tarefas estarem verificadas.

No painel do lab, anote a REGIÃO e a ZONA. Todos os recursos ficam nelas, salvo indicação diferente.

Onde o console não basta O console atual não cria pool de destino (tarefa 2) nem permite escolher o nome do proxy HTTP (tarefa 3). Como o roteiro exige os nomes www-pool e http-lb-proxy, essas partes são feitas com poucos comandos no Cloud Shell. Todo o resto é pelo console.

Tarefa 1: criar três servidores web20 pontos

O que o roteiro pede: três VMs (web1, web2, web3) com Apache e a regra de firewall www-firewall-network-lb liberando HTTP.

Criar cada VM (repita 3 vezes)

  1. Menu de navegação (☰) › Compute Engine › Instâncias de VM › Criar instância.
  2. Nome: web1 (depois web2 e web3). Região/Zona: REGIÃO / ZONA.
  3. Configuração da máquina: série E2, tipo e2-small.
  4. SO e armazenamento › Alterar: sistema operacional Debian, versão Debian GNU/Linux 12 (bookworm) (é a debian-12 do roteiro).
  5. Rede › Tags de rede: network-lb-tag.
  6. Avançado › Automação › Script de inicialização: cole o script do roteiro, trocando web-number pelo nome da VM: 
    #!/bin/bash
apt-get update
apt-get install apache2 -y
service apache2 restart
echo "Servidor da web: web1" | tee /var/www/html/index.html
  7. Mantenha o resto padrão e clique em Criar.

Criar a regra de firewall

  1. Menu › Rede VPC › Firewall › Criar regra de firewall.
  2. Nome: www-firewall-network-lb · Rede: default · Direção: Entrada · Ação: Permitir.
  3. Destinos: Tags de destino especificadas › network-lb-tag.
  4. Intervalos IPv4 de origem: 0.0.0.0/0 · Protocolos e portas: TCP 80.

Conferir: em Instâncias de VM, clique no IP externo de cada VM. A página deve mostrar "Servidor da web: web1" (ou web2, web3).

Tarefa 2: configurar o balanceador de rede35 pontos

O que o roteiro pede: IP externo estático network-lb-ip-1, pool de destino www-pool e encaminhamento na porta 80.

Pelo console: reservar o IP estático

  1. Menu › Rede VPC › Endereços IP › Reservar endereço IP externo estático.
  2. Nome: network-lb-ip-1 · Versão: IPv4 · Tipo: Regional · Região: REGIÃO. Clique em Reservar.
Por comando (o console não cria pool de destino) Abra o Cloud Shell (ícone >_ no topo) e rode, trocando REGIÃO e ZONA: 
gcloud compute http-health-checks create basic-check

gcloud compute target-pools create www-pool \
  --region=REGIÃO --http-health-check basic-check

gcloud compute target-pools add-instances www-pool \
  --instances web1,web2,web3 --instances-zone=ZONA

gcloud compute forwarding-rules create www-rule \
  --region=REGIÃO --ports 80 \
  --address network-lb-ip-1 --target-pool www-pool

Conferir: em Serviços de rede › Balanceamento de carga aparece o balanceador com o pool www-pool. Abra o IP network-lb-ip-1 no navegador e atualize algumas vezes: a resposta alterna entre web1, web2 e web3.

Tarefa 3: criar o balanceador HTTP45 pontos

O que o roteiro pede: modelo lb-backend-template, grupo gerenciado lb-backend-group, firewall fw-allow-health-check, IP lb-ipv4-1, verificação http-basic-check, mapa de URL web-map-http e proxy http-lb-proxy.

1. Modelo de instância (console)

  1. Menu › Compute Engine › Modelos de instância › Criar modelo de instância.
  2. Nome: lb-backend-template · Local: Regional, REGIÃO.
  3. Tipo de máquina: e2-medium · Disco de inicialização: Debian 12 (igual às VMs da tarefa 1).
  4. Rede › Tags de rede: allow-health-check.
  5. Automação › Script de inicialização (recomendado, para o teste final mostrar a página): 
    #!/bin/bash
apt-get update
apt-get install apache2 -y
a2ensite default-ssl
a2enmod ssl
vm_hostname="$(curl -H "Metadata-Flavor:Google" \
http://169.254.169.254/computeMetadata/v1/instance/name)"
echo "Page served from: $vm_hostname" | tee /var/www/html/index.html
systemctl restart apache2

2. Grupo gerenciado de instâncias (console)

  1. Compute Engine › Grupos de instâncias › Criar grupo de instâncias › Novo grupo gerenciado de instâncias (sem estado).
  2. Nome: lb-backend-group · Modelo: lb-backend-template · Local: Zona única, ZONA.
  3. Escalonamento automático: mínimo 2 instâncias.
  4. Mapeamento de portas: adicione a porta nomeada http › 80.

3. Firewall para as verificações de integridade (console)

  1. Rede VPC › Firewall › Criar regra de firewall.
  2. Nome: fw-allow-health-check · Rede: default · Entrada · Permitir.
  3. Tags de destino: allow-health-check.
  4. Intervalos de origem: 130.211.0.0/22 e 35.191.0.0/16 · TCP 80.

4. IP externo global (console)

  1. Rede VPC › Endereços IP › Reservar endereço IP externo estático.
  2. Nome: lb-ipv4-1 · IPv4 · Tipo: Global.
5. Balanceador por comando (os nomes exigidos não são configuráveis no console) 
gcloud compute health-checks create http http-basic-check --port 80

gcloud compute backend-services create web-backend-service \
  --protocol=HTTP --port-name=http \
  --health-checks=http-basic-check --global

gcloud compute backend-services add-backend web-backend-service \
  --instance-group=lb-backend-group \
  --instance-group-zone=ZONA --global

gcloud compute url-maps create web-map-http \
  --default-service web-backend-service

gcloud compute target-http-proxies create http-lb-proxy \
  --url-map web-map-http

gcloud compute forwarding-rules create http-content-rule \
  --address=lb-ipv4-1 --global \
  --target-http-proxy=http-lb-proxy --ports=80

Conferir (pelo console): Serviços de rede › Balanceamento de carga › clique em web-map-http. Abra http://IP-do-balanceador/. Pode levar de 3 a 5 minutos; aparece "Page served from: lb-backend-group-xxxx".

Erros comuns
  • VM em zona errada ou sem a tag de rede: o firewall não se aplica.
  • Esquecer a porta nomeada http:80 no grupo: o serviço de back-end não encontra a porta.
  • Testar o HTTP antes de 5 minutos e achar que falhou. Aguarde e atualize.
Estratégia de resolução preparada para a turma. Siga sempre o roteiro do laboratório: os nomes, a região e a zona mostrados no painel do lab têm prioridade sobre qualquer exemplo desta página.
