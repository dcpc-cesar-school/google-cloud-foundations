Antes de começar

Regras de ouro
  • Abra o lab em janela anônima e use só o usuário e a senha do laboratório.
  • Os valores em amarelo (nomes, região e zona) mudam a cada execução: copie do painel do lab, à esquerda do roteiro.
  • Faça pelo console. Use comandos apenas onde esta página indicar, e sempre no Cloud Shell do projeto do lab.
  • Ao final de cada tarefa, clique em Verificar meu progresso. Se não passar, leia a mensagem, corrija e verifique de novo.
  • Não clique em Terminar o laboratório antes de todas as tarefas estarem verificadas.

No painel do lab, anote: DATASET, TABELA, BUCKET, REGIÃO e os dois arquivos de resultado das tarefas 3 e 4 (ARQUIVO TAREFA 3 e ARQUIVO TAREFA 4).

Onde o console não basta Tarefa 2: o roteiro exige um comando hdfs dentro do cluster. Tarefas 3 e 4: as APIs não têm tela de uso no console; são chamadas por comando no Cloud Shell e o resultado é enviado ao bucket.

Tarefa 1: job simples no Dataflow25 pontos

Preparar o destino (console)

  1. Menu › BigQuery › Explorer › três pontos ao lado do projeto › Criar conjunto de dados › ID: DATASET.
  2. No dataset › Criar tabela › nome TABELA. Para o esquema, siga a dica que o roteiro mostra ao expandir.
  3. Cloud Storage › Buckets › Criar › nome BUCKET (o roteiro pede este bucket).

Criar o job (console)

  1. Menu › Dataflow › Jobs › Criar job com base em modelo.
  2. Nome do job: livre · Endpoint regional: REGIÃO.
  3. Modelo: em "Processar dados em massa (lote)", escolha Arquivos de texto do Cloud Storage para o BigQuery.
  4. Preencha conforme a tabela do roteiro:
    CampoValor
    Arquivos de entradags://spls/gsp323/lab.csv
    Esquema do BigQuerygs://spls/gsp323/lab.schema
    Tabela de saídaPROJETO:DATASET.TABELA
    Diretório temporário do BigQuery e local temporáriopastas no BUCKET, como no roteiro
    UDF em JavaScript (parâmetros opcionais)gs://spls/gsp323/lab.js, nome transform
    Tipo de máquina (parâmetros opcionais)desmarque o padrão › e2-standard-2
  5. Executar job. Aguarde o status Concluído antes de verificar.

Tarefa 2: job simples do Spark25 pontos

Criar o cluster (console)

  1. Menu › Managed Service for Spark (Dataproc) › Clusters › Criar cluster › Cluster no Compute Engine.
  2. Região: REGIÃO · Série de máquinas: E2.
  3. Nó do administrador: e2-standard-2, disco permanente equilibrado, 100 GB.
  4. Nós de trabalho: 2, e2-standard-2, disco permanente equilibrado.
  5. Desmarque Configurar todas as instâncias para que tenham apenas endereços IP internos. Clique em Criar.
Por comando (exigido pelo roteiro) Compute Engine › Instâncias de VM › SSH no nó administrador (nome terminado em -m) e rode: 
hdfs dfs -cp gs://spls/gsp323/data.txt /data.txt

Enviar o job (console)

  1. No cluster › Enviar job.
  2. Tipo: Spark · Classe principal: org.apache.spark.examples.SparkPageRank.
  3. Arquivos jar: file:///usr/lib/spark/examples/jars/spark-examples.jar · Argumentos: /data.txt.
  4. Máximo de reinicializações por hora: 1. Envie e aguarde Concluído.

Tarefa 3: API Speech-to-Text25 pontos

Criar a chave de API (console)

  1. Menu › APIs e serviços › Credenciais › Criar credenciais › Chave de API. Copie a chave.
Por comando (Cloud Shell) 
export API_KEY=SUA_CHAVE

cat > request.json <<EOF
{"config": {"encoding": "FLAC", "languageCode": "en-US"},
 "audio": {"uri": "gs://spls/gsp323/task3.flac"}}
EOF

curl -s -X POST -H "Content-Type: application/json" --data-binary @request.json \
 "https://speech.googleapis.com/v1/speech:recognize?key=$API_KEY" > result.json

gcloud storage cp result.json ARQUIVO-DA-TAREFA-3
Use o caminho exato do painel (gs://...) no último comando.

Conferir (console): no bucket, o objeto enviado deve ter Content-Type application/json (veja em "Editar metadados").

Tarefa 4: API Natural Language25 pontos

Por comando (Cloud Shell) 
gcloud ml language analyze-entities --content="Old Norse texts portray Odin as one-eyed and long-bearded, frequently wielding a spear named Gungnir and wearing a cloak and a broad hat." > result.json

gcloud storage cp result.json ARQUIVO-DA-TAREFA-4

Copie o texto sobre Odin direto do roteiro, para não errar nenhuma palavra. Confira o Content-Type application/json no bucket.

Erros comuns
  • Verificar o progresso antes de o job terminar (Dataflow e Spark levam alguns minutos).
  • Esquecer o comando hdfs antes do job Spark: o job falha por não achar /data.txt.
  • Enviar o resultado para outro caminho que não o do painel.
Estratégia de resolução preparada para a turma. Siga sempre o roteiro do laboratório: os nomes, a região e a zona mostrados no painel do lab têm prioridade sobre qualquer exemplo desta página.
