🎯 Cenário e objetivo clique para abrir

Você é engenheiro de dados júnior da Jooli Inc. e vai mostrar, na prática, as etapas mais comuns de um projeto de dados no Google Cloud: guardar dados brutos, carregá-los num lugar onde possam ser consultados, processá-los em escala e extrair informação de áudio e de texto com modelos de IA prontos do Google. Use a Region e os nomes exatamente como aparecem no painel e nas instruções do lab.

🧰 Os serviços usados no lab

  • Cloud Storage: o "HD" da nuvem. Guarda arquivos de qualquer tipo (CSV, áudio, JSON) em buckets. No lab, é de onde vêm os dados de entrada e para onde vão os resultados.
  • BigQuery: o banco de dados para análise. Guarda tabelas enormes e responde a consultas em SQL em segundos. Os dados ficam organizados em datasets (conjuntos de dados) e tabelas.
  • Dataflow: o "encanamento" de dados. Roda pipelines que leem dados de um lugar, transformam e gravam em outro, criando e desligando as máquinas sozinho. Tem modelos prontos para os casos mais comuns.
  • Managed Service for Apache Spark (Dataproc): clusters de Apache Spark prontos em poucos minutos. O Spark divide um processamento grande entre várias máquinas, que trabalham em paralelo. No menu do console aparece como Managed Apache Spark.
  • Speech-to-Text: API de IA que transcreve áudio em texto. Você envia o áudio e recebe a transcrição em JSON.
  • Natural Language: API de IA que entende texto. Identifica entidades (pessoas, lugares, objetos), sentimento e assunto, e devolve o resultado em JSON.

🔗 O que cada tarefa faz

  • Tarefa 1 · Cloud Storage › Dataflow › BigQuery
    O que faz: cria o dataset BigQuery Dataset Name com a tabela Output Table Name e o bucket Cloud Storage Bucket Name; depois, um job do Dataflow lê o CSV lab.csv, aplica a função transform e grava o resultado nessa tabela.
    Para que serve: é um pipeline de ETL (extrair, transformar e carregar): deixa dados brutos prontos para análise com SQL, sem gerenciar servidores.
  • Tarefa 2 · Managed Service for Apache Spark (Dataproc)
    O que faz: cria um cluster na Region, copia o arquivo data.txt para o HDFS e roda o PageRank sobre ele.
    Para que serve: processar grandes volumes de dados em paralelo. O PageRank, que ranqueia páginas pelos links que recebem, é o exemplo clássico.
  • Tarefa 3 · Cloud Storage › Speech-to-Text › Cloud Storage
    O que faz: transcreve o áudio task3.flac e salva a transcrição em JSON em Cloud Speech Location.
    Para que serve: transformar áudio (atendimentos, reuniões, vídeos) em texto que pode ser pesquisado e analisado.
  • Tarefa 4 · Natural Language › Cloud Storage
    O que faz: identifica as entidades do texto sobre Odin e salva o resultado em JSON em Cloud Natural Language Location.
    Para que serve: descobrir automaticamente "do que o texto fala", para classificar, indexar ou alimentar outras análises.
💡 Na prática, o que o conjunto faz As quatro tarefas montam um pequeno fluxo de preparação de dados para machine learning:
  • dados estruturados (o CSV) entram no BigQuery pelo Dataflow, já tratados;
  • dados em grande volume são processados em paralelo com Spark;
  • dados não estruturados (áudio e texto livre) viram JSON organizado pelas APIs de ML e ficam guardados no Cloud Storage.
No fim, tudo está em formatos que podem ser consultados, cruzados e usados para treinar ou alimentar modelos. E sem você escrever nenhum modelo de ML: o trabalho é feito com serviços gerenciados e APIs prontas do Google.

Tarefa 1: job simples no Dataflow

Criar o dataset e a tabela do BigQuery

  1. Menu de navegação (☰) › BigQuery › Studio.
  2. No painel Explorer, ao lado do ID do projeto, clique em ⋮ › Create dataset.
  3. Dataset ID: BigQuery Dataset Name. Deixe o resto como está.
  4. Clique em Create dataset.
  5. Ao lado do dataset BigQuery Dataset Name, clique em ⋮ › Create table. Se o menu não abrir, clique no nome do dataset e, na página dele, use ⋮ › Create Table.
  6. Table: Output Table Name (só o nome da tabela).
  7. Schema: ative Edit as text e cole o esquema da dica das instruções do lab (clique em "Clique aqui para ver uma dica", logo abaixo de "Criar um bucket").
  8. Clique em Create table.
✅ É normal: ao abrir o BigQuery pela primeira vez aparecem um diálogo de boas-vindas e um painel de novidades. Clique em Done e feche o painel.

Criar o bucket

  1. Menu de navegação (☰) › Cloud Storage › Buckets e clique em Create.
  2. Name your bucket: Cloud Storage Bucket Name. Deixe o resto como está.
  3. Clique em Create.
✅ É normal: aparece o aviso Public access will be prevented. Clique em Confirm.

Criar o job do Dataflow

  1. Menu de navegação (☰) › View all products › Analytics › Dataflow › Jobs e clique em Create job from template.
  2. Job name: um nome à sua escolha, por exemplo lab-dataflow.
  3. Regional endpoint: selecione a opção Region.
  4. Dataflow template: digite Text Files on Cloud Storage to BigQuery no filtro e, em Process Data in Bulk (batch), selecione a opção Text Files on Cloud Storage to BigQuery (a primeira, sem "with ..." no final).
⚠️ Os campos de caminho já têm gs:// Nos campos de arquivo e pasta, o gs:// já aparece fixo à esquerda. Cole o caminho sem o gs://. Se colar com ele, o campo fica gs:// gs://... e mostra o erro "Bucket names may only contain lowercase letters...". Para os valores em amarelo, cole o valor das instruções do lab e apague o gs:// do começo.
  1. Preencha os campos com os valores da tabela das instruções do lab:
    • Cloud Storage Input File(s): spls/gsp323/lab.csv
    • Cloud Storage location of your BigQuery schema file: spls/gsp323/lab.schema
    • BigQuery output table: Output Table Name no formato projeto:dataset.tabela (este campo não tem gs://)
    • Temporary directory for BigQuery loading process: Temporary BigQuery Directory (sem o gs://)
    • Temporary location: Temporary Location (sem o gs://)
  2. Abra Optional Parameters:
    • JavaScript UDF path in Cloud Storage: spls/gsp323/lab.js
    • JavaScript UDF name: transform
    • Desmarque Use default machine type. Em Series, troque N1 por E2. Depois, em Machine type, selecione a opção e2-standard-2.
  3. Clique em Run job.
⏱️ Vai demorar alguns minutos (3 a 5) para concluir. Aguarde até as 4 etapas do gráfico ficarem com o status Succeeded. Aproveite para começar a tarefa 2.
✅ É normal: logo após o Run job, a tela mostra "The graph is still being analyzed". Espere o gráfico aparecer.

Volte às instruções do lab no Google Skills e clique em Verificar meu progresso da tarefa 1.

Tarefa 2: job simples do Spark

Criar o cluster

  1. Menu de navegação (☰) › View all products › Analytics › Managed Apache Spark › Clusters e clique em Create cluster › Cluster on Compute Engine.
⚠️ Use o formulário clássico de criação Se abrir a tela "Create cluster" com Define your cluster shape (Standard / Development / High availability), ela não oferece a série E2 e começa em outra região. Use o formulário clássico, "Create an Apache Spark cluster on Compute Engine": abrir o formulário clássico. Confira no topo do console se o projeto é o do lab.
  1. Region: selecione a opção Region. Cluster type: deixe Standard (1 master, N workers).
  2. Desça até Advanced configurations (optional) e clique em Show configuration options. Abra Infrastructure.
  3. Manager node, nesta ordem:
    • Primary disk type: Balanced Persistent Disk (primeiro, senão a série E2 não aparece);
    • Series: E2 · Machine type: e2-standard-2;
    • Primary disk size: 100 GB.
  4. Worker nodes, na mesma ordem: Primary disk type Balanced Persistent Disk · Series E2 · Machine type e2-standard-2 · Number of worker nodes 2.
  5. Abra Other e, em Internal IP only, desmarque Configure all instances to have only internal IP addresses.
  6. Clique em Create.
✅ É normal: uma faixa vermelha avisa sobre imagens antigas (1.x e 2.0) que serão desativadas. E, nos nós, uma caixa diz "Looking for older machine type generations?": é ela que explica que o tipo de disco precisa ser trocado primeiro. Nenhum dos dois é erro.
⏱️ Vai demorar alguns minutos (2 a 3) para concluir. Aguarde até o status do cluster ficar Running (ícone verde). Enquanto isso, faça as tarefas 3 e 4.

Copiar o arquivo para o HDFS

  1. Menu de navegação (☰) › Compute Engine › VM instances.
  2. Na linha do nó administrador (nome terminado em -m), clique em SSH. Abre uma janela nova (ou aba) com um terminal. Se pedir, clique em Authorize.
Por comando (as instruções do lab exigem) SSH do nó -m Na janela SSH, confira se o prompt termina em @...-m:~$ e rode: 
hdfs dfs -cp gs://spls/gsp323/data.txt /data.txt
✅ É normal: o comando mostra várias linhas com INFO (métricas, latência). Se não aparecer ERROR, a cópia deu certo. Se aparecer hdfs: command not found, você está no Cloud Shell: rode na janela SSH do nó -m.

Enviar o job

  1. Volte a Managed Apache Spark › Clusters, clique no nome do cluster e em Submit job.
  2. Job type: selecione a opção Spark (Scala / Java).
  3. Main class: org.apache.spark.examples.SparkPageRank
  4. Jar files: file:///usr/lib/spark/examples/jars/spark-examples.jar (tecle Enter)
  5. Arguments: /data.txt (tecle Enter)
  6. Max restarts per hour: 1
  7. Clique em Submit.
⏱️ Vai demorar 1 a 2 minutos para concluir. Aguarde até o status do job ficar Succeeded. Se a página não atualizar, abra Jobs (and Batches) no menu lateral.
✅ É normal: na lista de jobs aparece um aviso sobre chaves CMEK. Pode ignorar.

Volte às instruções do lab no Google Skills e clique em Verificar meu progresso da tarefa 2.

Tarefa 3: API Speech-to-Text

Criar a chave de API

  1. Menu de navegação (☰) › APIs & Services › Credentials.
  2. Clique em Create credentials › API key. Em telas estreitas, o botão fica no ⋮ ao lado de "Credentials".
  3. Select API restrictions: digite Speech no filtro, marque Cloud Speech-to-Text API e clique em OK. Esse campo é obrigatório.
  4. Application restrictions: deixe None.
  5. Clique em Create.
  6. Na tela API key created, copie a chave do campo Your API key e clique em Close.
✅ É normal: a página Credentials pede para configurar a "OAuth consent screen", e a tela da chave mostra um quadro "Service account required". Nenhum dos dois é necessário neste lab.
Por comando Cloud Shell No topo do console, clique em Activate Cloud Shell (ícone >_). Clique em Continue e, se pedir, em Authorize. O prompt termina em @cloudshell:~ (projeto)$. Rode os blocos um de cada vez, esperando cada um terminar.

1. Guardar a chave de API:

export API_KEY=Your API key

2. Criar o arquivo da requisição:

cat > request.json <<EOF
{"config": {"encoding": "FLAC", "languageCode": "en-US"},
 "audio": {"uri": "gs://spls/gsp323/task3.flac"}}
EOF

3. Chamar a API e salvar o resultado:

curl -s -X POST -H "Content-Type: application/json" --data-binary @request.json \
 "https://speech.googleapis.com/v1/speech:recognize?key=$API_KEY" > result.json

4. (Opcional) Conferir o resultado: deve aparecer um "transcript", e não um "error".

cat result.json

5. Enviar o resultado ao bucket:

gcloud storage cp result.json Cloud Speech Location
O arquivo .json é enviado com Content-Type application/json, como as instruções do lab pedem.

Volte às instruções do lab no Google Skills e clique em Verificar meu progresso da tarefa 3.

Tarefa 4: API Natural Language

Por comando Cloud Shell No mesmo Cloud Shell da tarefa 3 (não na janela SSH do cluster), rode os blocos um de cada vez. Se o Cloud Shell perguntar se quer ativar a API, digite y e tecle Enter.

1. Analisar o texto sobre Odin:

gcloud ml language analyze-entities --content="Old Norse texts portray Odin as one-eyed and long-bearded, frequently wielding a spear named Gungnir and wearing a cloak and a broad hat." > result.json

2. Enviar o resultado ao bucket:

gcloud storage cp result.json Cloud Natural Language Location

Volte às instruções do lab no Google Skills e clique em Verificar meu progresso da tarefa 4.

✅ É normal: às vezes o Verificar meu progresso só fica verde no segundo clique, e o placar no topo demora a atualizar. Se as 4 tarefas estiverem verdes e o placar não mostrar 100, recarregue a página do lab.
⚠️ Erros comuns clique para abrir
  • Verificar o progresso antes de o job terminar: Dataflow e Spark levam alguns minutos. Espere o status Succeeded.
  • Colar gs:// nos campos do Dataflow que já têm o prefixo: o campo fica gs:// gs://... e dá erro. Cole sem o gs://.
  • Não achar a série E2 no cluster: troque antes o Primary disk type para Balanced Persistent Disk, e use o formulário clássico de criação.
  • Rodar o hdfs no Cloud Shell (hdfs: command not found): ele só existe na janela SSH do nó -m.
  • Rodar os comandos das tarefas 3 e 4 no SSH do cluster: a verificação não passa. Use o Cloud Shell.
  • Esquecer o comando hdfs antes do job do Spark: o job falha por não achar /data.txt.
  • Criar o job ou o cluster em outra região: use sempre a Region do painel. O formulário de cluster pode vir com outra região selecionada.
  • Enviar o resultado para outro caminho: use exatamente Cloud Speech Location e Cloud Natural Language Location.
  • Mudar o texto sobre Odin: copie o comando inteiro desta página ou das instruções do lab.
  • Nomes de botões diferentes dos desta página: a tradução automática do navegador está ligada. Veja "Antes de começar".
